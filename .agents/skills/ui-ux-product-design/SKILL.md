# FleetEase UI/UX Product Design

FleetEase is an established product. Improvement means refinement, not replacement.

Before changing UI, inspect the existing page, neighboring modules, shared components, tokens, navigation and responsive behavior. Reuse established patterns when they are good.

Avoid interchangeable SaaS cards, excessive gradients, meaningless decorative icons, giant empty dashboard areas, repetitive rounded-card layouts, generic AI copy and charts that add no decision value.

Prioritize:
1. What needs attention now.
2. What action the user can take.
3. What changed.
4. Supporting detail.

Design and verify applicable empty, loading, partial, success, error, permission, disabled, hover, focus, selected and destructive/recovery states.

Forms need clear labels, sensible defaults, inline validation, preserved input on recoverable errors, explicit pending state and actionable errors.

Treat tablet as a first-class viewport. Do not simply stack every desktop card vertically.

Use semantic controls, keyboard focus, readable contrast and native semantics before ARIA.

When possible, inspect rendered desktop and tablet views before adding decorative polish.
